# Checkpoint 3 — Core Missing Workflow

## Progress

- Checkpoint 2 preview APK is available for independent device testing; its build link is recorded in `CHECKPOINT_2.md`.
- Added the first missing-workflow migration, `202610220012_missing_draft_foundation.sql`. Reports begin as private drafts in the shared `reports` table. One unfinished missing draft is allowed per animal, and a separate index will prevent duplicate active missing reports.
- Draft saves and deletion use protected functions. Only an active member with a completed profile can save a draft for their own safe animal. Repeated saves resume the same draft, and members cannot write report rows or status directly.
- Drafts are creator-only, including against other members and administrators. No anonymous or public report surface is enabled yet.
- Account deletion removes unfinished drafts. Deleting a source animal also removes its unfinished missing draft, and the in-app confirmation now states this explicitly.
- Expo's current SDK 57 compatibility check required patch updates to the pinned `expo` and `expo-location` versions. Both were updated without adding dependencies.
- The Supabase migration was applied and the user ran `003_missing_drafts.test.sql`: all 26 assertions passed.
- The Report tab now opens Select Missing Animal and Confirm Current Appearance. Safe animals can start or resume a private draft, capture incident-only accessories and appearance notes, confirm the profile photos, save, and delete a draft. Back warns before discarding unsaved edits. Missing-report publication remains disabled.
- The user confirmed on-device selection, save/recovery, deletion and Android Back tests passed.
- Added Last-Seen Details (screen 4.3) to the private draft. It records the last-seen date/time and accuracy, circumstance and optional observed details; checks real dates, future times and noticed-missing chronology. Incomplete entries can be saved for later. Suspected theft shows separate SAPS advice. No report is published by this step.
- Before device testing, replaced manual date/time entry on screen 4.3 with native date and 24-hour time pickers, including the optional noticed-missing date/time. `@react-native-community/datetimepicker` 9.1.0 is pinned for Expo SDK 57 and configured in `app.config.js`. This native dependency requires reinstalling the Android development build; a Metro refresh alone is insufficient.
- Native debug build and USB reinstall completed after explicitly generating the picker's Android codegen artifacts. Picker interaction and date/time recovery still need physical-device verification.
- Simplified screen 4.3 to two date-and-time choices: required last confirmed sighting and optional time the absence was noticed. Each choice walks through date then 24-hour time; the underlying private draft format and validation are unchanged. Added an on-screen bullet guide explaining each field and a confirmation after either full or incomplete save, with an option to return to Report.
- Replaced separate direction and people/vehicles inputs with one optional "Travelled towards" answer and explicit Known/Unknown choices. The answer accepts a direction or landmark plus only directly observed person/vehicle details; older drafts' separate observations are combined into the visible answer when reopened. Unknown clears the travel answer. No database migration or new dependency is needed.
- Added Last-Seen Location (screen 4.4) to the private missing draft. A complete last-seen detail save now continues to location. Members can enter an area manually, deliberately copy home *area only* (never home coordinates), or capture their current place once with foreground permission after confirming they are at the sighting place. Public precision defaults to suburb only; street/public-landmark-name sharing is optional, with house numbers rejected. Exact coordinates and private addresses are never previewed or eligible for public missing reports. Older private drafts with an exact-public choice are downgraded to suburb-only when reopened. Draft save/recovery and validation remain private through the existing protected RPC. A map picker awaits the map-provider decision; publication is still disabled.
- Added Urgency, Behaviour and Contact (screen 4.5) after last-seen location. The member can mark known urgent needs, choose an approach instruction and bite/scratch/kick warning, and choose in-app, phone or WhatsApp response channels. In-app is the default; phone and WhatsApp require the corresponding profile capability and are opt-in per report. Only channel flags—not the phone number—are stored in the private draft. Completed and incomplete saves can be recovered; final preview and publication remain disabled. No database migration or new dependency was needed.
- Added private Preview Missing Report (screen 4.6) after safety/contact save. It builds an allowlisted proposed public view of the animal, last-seen facts and location, safety notes, reporter display name and only enabled contact channels. It does not show raw draft JSON, exact coordinates, private identifiers or unapproved phone contact. Stale/incomplete steps are flagged with edit links, and the member reviews three accuracy/privacy/update acknowledgements. These acknowledgements are not persisted; publication remains disabled pending server-side public projection, snapshot and privacy-policy work. No database migration or new dependency was needed.
- Prepared the website privacy-policy source and built HTML to match the approved street-or-broader public-location rule and remind reporters not to put private details in free text or photos. These local files are not deployed. Public report publication stays disabled until the live page is updated and server-side privacy/RLS tests pass.
- Enabled Profile › My Reports for private missing drafts. Members can see saved drafts, continue the existing wizard, delete a draft after confirmation, or start another missing report. This reuses the existing creator-only report reads and protected delete function; it does not enable publication or need a new migration.
- Appearance review now shows only `report_eligible` animal photos and saves the member's selected photo IDs separately from the full photo-list freshness check. The proposed public preview displays only those selected photos (or a placeholder if none). Invalid, changed or unavailable selections require review; no report photo is made public yet.
